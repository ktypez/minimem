ระดับที่หนึ่ง: บนเครื่องตัวเอง

  • หนึ่ง process Bun หนึ่งไฟล์ SQLite โหมด WAL
  • FTS5 trigram และ index เวกเตอร์ถ้าตั้งค่า embedding
  • ตัวเลขทั้งหมดวัดจาก instance จริงบนเครื่องนี้

ระดับที่สอง: ผ่าน LAN

  • REST และ MCP บน origin เดียวกัน ผ่าน Caddy
  • client ทุกตัวพูด MCP ได้ 16 tool ไม่ต้องเขียน parser
  • ตรวจสุขภาพได้โดยไม่ต้อง bind พอร์ต

สามข้อที่เรายึด

minimem

คลังความจำกลางของเครื่องมือ สำหรับ agent ที่ลงมือทำจริง หนึ่งไฟล์ SQLite หนึ่ง process หนึ่งแหล่งความจริง เขียนไว้ให้คนอ่านก่อน แล้วค่อยให้ machine อ่าน

1

โมเดลล้มก็ข้าม ไม่เดา

ความจำที่ซ้ำเกินไปเสียหายน้อยกว่าความจำที่หายไปเงียบ ๆ โมเดลที่ล้มถูกข้าม ไม่ถูกเดาแทน

2

ตัวเลขต้องวัด ไม่ใช่ประมาณ

ตัวชี้วัดแล้วมีเหตุผลกำกับทุกตัว ถ้าจะเปลี่ยน ให้รัน test ก่อนแล้วเขียนว่าทำไม

3

เช็คที่ผ่านได้ผ่านไม่ได้ ยังไม่ใช่เช็ค

สคริปต์ต้องเป็นเจ้าของเซิร์ฟเวอร์ตัวเอง หา port ว่างแล้วปิดมันตอนจบ ไม่ใช้ของที่คนอื่นเปิดไว้

เริ่มจากสามคำสั่ง

คลังเปิดอยู่ที่ localhost:3100 และมีโทเคนป้องกัน ถ้าเปิด auth ไว้ให้ใส่ Authorization: Bearer <token> ทุกคำสั่ง

1. เขียนหนึ่งเรื่อง

curl -X POST localhost:3100/memories \
  -H 'content-type: application/json' \
  -d '{"text":"minimem รันที่ :3100","tags":["infra"]}'

2. ค้นกลับ

curl 'localhost:3100/memories/search?q=health+check'

3. ถามว่าใครพูดเมื่อไหร่

curl 'localhost:3100/memories/recall?q=health+check'
ผ่าน MCP เลยก็ได้ มี 16 tool: memory_save, memory_search, memory_recall, memory_trust, memory_supersede, lesson_save, handoff_write, lease_acquire และอีก ๆ วิธีตั้งค่าต่อ client อยู่ใน docs/INSTALL.md

สามคำสั่งที่ทำให้คลังนี้ต่างจากโฟลเดอร์ข้อความ

คลังเก็บข้อความได้ง่าย สิ่งที่ยากคือรู้ว่าข้อความไหนคือของเดิมและของไหนทับกัน สามคำสั่งนี้จัดการเรื่องนั้น

recall

ค้นแล้วได้อันดับ พร้อมบอกว่าเจอด้วยคำ (match), ความหมาย (cos), อายุ (age_days), ใครพูด (agent_source), เชื่อได้แค่ไหน (trust) และอันเก่าที่ถูกบัง (shadowed) เรียกด้วย ?mode=keyword เพื่อบังคับเส้นทาง FTS5 ล้วน

trust

สำรอง ตรวจสุขภาพ และจัดการบริการ

คลังคือไฟล์เดียว การดูแลจึงเรียบง่าย แต่มีข้อที่ต้องระวัง

สำรองให้ถูกวิธี

sqlite3 /path/minimem.db ".backup out.db"     # ไฟล์ที่ยังรันอยู่
sqlite3 /path/minimem.db "VACUUM INTO 'out.db'"   # คัดลอกที่สมบูรณ์ รวม WAL

การ cp ไฟล์ตอนที่บริการยังรันอยู่จะได้เวกเตอร์เก่าและข้อมูลที่ยังไม่ถูก flush ใช้ VACUUM INTO หรือ .backup เท่านั้น

ตรวจไฟล์โดยไม่ต้องเปิดพอร์ต

bun run server.ts --check

MINIMEM_DB_PATHที่อยู่ไฟล์ SQLite ค่าเริ่มต้น ./data/minimem.db
AUTH_ENABLED1 คือเปิดล็อก, 0 คือเปิดทุกคน เปิดแล้วห้าม bind 0.0.0.0
MINIMEM_MCP1 คือเปิด POST /mcp
CF_AI_TOKEN / CF_ACCOUNT_IDถ้าตั้งแล้วจะมี semantic layer ไม่ตั้งก็เหลือ keyword อย่างเดียว
MINIMEM_ENVไฟล์ env ที่อ่านเข้ามา ไม่มี secret ใน command line
HYBRID_W_FTS / HYBRID_W_VEC / HYBRID_W_RECน้ำหนักการผสมอันดับ มีเหตุผลกำกับทุกตัว เปลี่ยนแล้วต้องรัน test
